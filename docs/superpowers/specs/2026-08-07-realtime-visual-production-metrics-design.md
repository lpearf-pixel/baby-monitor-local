# 实时视觉生产性能观测设计

**日期：** 2026-08-07

**状态：** 已批准，待实施

**阶段：** R3.5 i9 实机性能门

**上位规格：** `2026-08-06-realtime-visual-candidate-layer-design.md`

## 1. 背景与目标

Intel i9 实机已经证明固定 OpenVINO 后端可用，语义结果可产生，视觉 worker、
视频流和 Dashboard 均保持健康。独立进程首帧处理耗时为 `243.931ms`；随后只对
生产 worker 采样 45 秒，平均 CPU 为一个逻辑核心的 `96.38%`、整机容量的
`6.02%`，峰值约两个逻辑核心，RSS 峰值为 `446.97MB`。这些数据证明资源没有
失控，但不能证明生产 worker 当前处于 5、3 或 1 FPS，也不能给出稳定窗口的
P50、P95 和最大处理时间。

本阶段增加一个仅限本机、脱敏、聚合的生产观测面，使 `make alpha-visual-status`
可以报告：

- `realtime_fps`；
- `sample_count`；
- `processing_p50_ms`；
- `processing_p95_ms`；
- `processing_max_ms`；
- `realtime_model_state`。

该观测面只用于确认 5/3/1 FPS 自动降载和 i9 性能门，不改变候选规则、风险规则、
模型门限、Qwen 调度或告警行为。

## 2. 方案选择

| 方案 | 优点 | 风险 | 决定 |
|---|---|---|---|
| worker 原子写入本地状态 JSON，命令只读 | 无新端口、边界小、可脚本化验收 | 需要处理陈旧与半写状态 | 采用 |
| 在 Dashboard 或 worker 增加 HTTP 指标端点 | 易于远程读取 | 扩大监听和鉴权边界，把 R3.5 与 Dashboard 耦合 | 不采用 |
| 从视觉日志解析指标 | 改动表面较少 | 日志轮转、解析和隐私审计脆弱，不能形成稳定契约 | 不采用 |

## 3. 组件与数据流

`RealtimeLoadController` 继续独占最近 10 秒的有界处理耗时窗口。每次成功分析后，
它返回当前目标 FPS、窗口样本数、nearest-rank P50、nearest-rank P95、最大耗时和
可选的降级/恢复转换。统计值只来自 `RealtimeObservation.processing_ms`，不包含
输入帧、模型张量或候选结果。

`VisualWorker` 把上述负载状态与 analyzer 的稳定模型状态组合成冻结的脱敏快照，
再调用可选状态回调。回调失败只形成稳定错误码，不能停止取流、帧健康检查、
实时分析、Qwen 帧环或常规复核。

生产入口把快照交给单用途状态写入器。写入器先在目标目录创建同文件系统临时文件，
设置权限为 `0600`，完成 JSON 写入和 flush 后使用原子替换发布到
`runtime/status/realtime-visual.json`。目标目录和文件均属于已忽略的 runtime，
不得进入 Git。

`make alpha-visual-status` 只在视觉 worker 运行时调用只读状态命令。命令严格解析
schema，按固定键顺序输出聚合字段；文件缺失、陈旧或非法时仅输出稳定状态码，
不得输出路径、异常文本或文件原文。

## 4. 状态契约

状态文件使用固定 `schema_version: 1`，只允许以下字段：

| 字段 | 类型与范围 | 含义 |
|---|---|---|
| `schema_version` | 固定整数 `1` | 本地状态格式版本 |
| `written_at_unix` | 有限非负浮点数 | 原子发布时钟，用于陈旧判断 |
| `realtime_fps` | `1 \| 3 \| 5` | 自动负载控制器当前目标档位 |
| `sample_count` | `1..51` | 最近 10 秒有界窗口的有效分析样本数 |
| `processing_p50_ms` | 有限非负浮点数 | 窗口 nearest-rank P50 |
| `processing_p95_ms` | 有限非负浮点数 | 窗口 nearest-rank P95 |
| `processing_max_ms` | 有限非负浮点数 | 窗口最大处理耗时 |
| `realtime_model_state` | `available \| degraded` | 固定模型后端当前状态 |

统计关系必须满足
`processing_p50_ms <= processing_p95_ms <= processing_max_ms`。数值统一四舍五入到
三位小数。窗口仍限制为最近 10 秒，因此 5 FPS 时最多约 51 个边界样本；实现不
创建长期时序数据库，也不累计整夜明细。

状态命令默认把超过 15 秒未更新的文件报告为 `realtime_metrics=stale`。缺失文件
报告 `realtime_metrics=unavailable`，schema 或数值非法报告
`realtime_metrics=invalid`。三种情况都以非零状态结束，以便验收脚本 fail closed；
输出不得包含目标路径或底层异常。

## 5. 隐私与安全边界

状态文件和命令不得包含或推导以下内容：

- JPEG、像素、图像摘要、模型张量或原始模型输出；
- 姿态数、人脸数、关键点、检测框、运动比例或候选类型；
- 床区、隐私遮罩、摄像头标识、私网地址或本地绝对路径；
- 宝宝或成人的身份、行为标签、家庭场景文字；
- Token、环境变量、底层异常或日志片段。

该文件只在 i9 本机保存最近聚合状态。它不是医疗记录、风险证据、家庭准确率记录
或 Dashboard 数据源。

## 6. 错误处理与生命周期

- 实时功能关闭时不创建状态文件，状态命令报告 `unavailable`。
- 分析失败时不伪造新的性能样本；worker 现有降级逻辑继续生效。
- 状态写入失败时 worker 只记录稳定健康码 `realtime_status_write_failed`，继续运行。
- worker 重启后首次成功分析覆盖旧文件；在此之前陈旧门禁止旧值通过验收。
- 读者只接受严格 schema 和有限数值；额外字段也视为非法，防止以后无意扩大输出。
- 不删除历史文件作为启动前提，避免为这项观测引入破坏性操作。

## 7. 自动化与实机验收

自动化测试必须证明：

1. 控制器从手算样本产生正确的 P50、P95、最大值和样本数；
2. 10 秒窗口淘汰旧样本，降级/恢复后统计契约保持一致；
3. worker 输出只含允许字段，回调失败不终止分析；
4. 写入器使用原子替换和 `0600` 权限，严格拒绝非法快照；
5. CLI 正确区分 available、unavailable、stale 和 invalid，且错误输出不泄露路径；
6. 部署命令只在 worker 运行时读取聚合状态，不新增监听端口；
7. 完整 Python、浏览器、编译、Shell、差异和敏感信息门禁继续通过。

i9 更新后连续运行至少 10 分钟，并保存命令行聚合输出。若 5 FPS 的生产 P95 不
超过 `180ms`，则 5 FPS 性能门通过；若自动稳定在 3 FPS，则要求生产 P95 不超过
`300ms`，并保留 5→3 的降级事实和测得的 P50/P95/最大值。稳定在 1 FPS、状态
陈旧、模型降级或指标非法均不能通过首期门，也不得通过修改既有门限绕过失败。

本阶段通过仍只证明性能和运行稳定性。空床、玩偶、成人、夜视、遮挡、蚊帐和
正常翻身的家庭场景准确率门继续独立验收，实时候选仍不能直接创建风险告警。
