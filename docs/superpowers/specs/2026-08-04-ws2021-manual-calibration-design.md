# WS2021 一次性人工标定设计

**日期：** 2026-08-04

**状态：** 待书面复核

**范围：** M2 / Task 8，仅标定；不包含自动读数、历史记录或环境告警

## 1. 目标

在现有鉴权 Dashboard 内提供一个一次性人工标定向导。用户先选择
`2×` 并把 WS2021 温湿度计拖到清晰位置，再冻结当前高清截图；向导引导用户
框选仪表、标记两个表盘的圆心与针尖，并为每个表盘标记至少三个已知刻度及
其数值。成功后在 i9 本机生成版本化标定文件，供后续读针模块使用。

摄像头、仪表或构图移动后必须重新标定。标定不是温湿度读数，也不触发告警。

## 2. 方案选择

采用 Dashboard 内标定向导，而不是命令行坐标输入或自动圆检测：

- 复用已经验证的 `2×/3×` 高清截图和拖动视野，避免再次设计取流链路；
- 用户直接点击真实像素，不需要人工换算坐标；
- 第一版不引入 OpenCV、自动找圆或新的常驻进程，控制实现与运行负担。

## 3. 用户流程

1. 用户在 Dashboard 选择 `2×`，把温湿度计拖到画面中央附近。
2. 点击“标定温湿度计”，页面冻结当前高清截图；标定期间实时画面继续在后台
   运行，但标记点只绑定到冻结帧。
3. 用户拖出一个矩形，框住完整 WS2021 仪表。
4. 按向导顺序标定湿度表盘：圆心、当前针尖、三个或更多刻度点，并为每个刻度
   输入 `%RH` 数值。
5. 按同样顺序标定温度表盘，并为刻度输入 `°C` 数值。
6. 页面显示最终叠加预览。用户确认后保存；取消则不写任何文件。
7. 保存成功后显示标定版本、时间和“移动仪表或摄像头后需重新标定”的提示。

点位允许撤销上一步和重新开始。第一版不提供拖拽微调；点错时撤销后重标，
避免引入复杂编辑状态。

## 4. 坐标与数据模型

所有坐标保存为冻结截图中的归一化坐标，范围为 `[0, 1]`。标定文件同时记录：

- `schema_version: 1`；
- 创建时间；
- 高清截图使用的 `zoom`、`center_x`、`center_y`；
- 冻结帧宽高；
- 仪表矩形 ROI；
- `humidity` 与 `temperature` 两个表盘；
- 每个表盘的 `center`、`needle_tip` 和至少三个 `{point, value}` 刻度。

角度映射由后续读针模块根据“圆心→刻度点”计算。标定验证允许刻度跨越
`0°/360°`，不得通过简单数值排序破坏环形顺序。

固定输出位置：

```text
runtime/calibration/ws2021-v1.json
runtime/calibration/ws2021-reference.jpg
```

保存采用同目录临时文件后原子替换。再次标定覆盖当前版本；旧文件先复制到
`runtime/calibration/backups/`，备份数量限制为 3 份。

## 5. 校验与错误处理

保存前同时在浏览器和服务端执行闭合校验：

- 只接受 `zoom=2` 或 `zoom=3` 的高清截图；
- ROI 必须有正面积且完全位于图片内；
- 圆心、针尖和刻度点必须位于 ROI 内；
- 针尖和每个刻度点不能与圆心重合；
- 每个表盘至少三个刻度，数值和角度均不得重复；
- 湿度刻度限定为 `0–100 %RH`；温度刻度限定为 `-50–60 °C`；
- 不接受额外字段、客户端文件路径、流名称或上游地址。

任何失败都返回明确的字段级错误，且不得覆盖已有标定。冻结帧过大、格式异常、
高清源不可用或本地写入失败时，向导保留已标点位供重试，但不宣称保存成功。

## 6. 隐私与安全边界

- 标定入口继续使用 Dashboard 现有鉴权，不新增公开端口。
- 截图来源固定为现有受控高清截图链路，客户端不能指定任意 URL 或流。
- 家庭参考图与标定 JSON 只写入已忽略的 `runtime/calibration/`。
- 测试只使用程序生成的合成表盘，不提交真实家庭画面、私网地址或摄像头凭据。
- API 响应只返回标定状态和非敏感元数据，不回显本地绝对路径。

## 7. 组件边界

- `services/gauge/calibration.py`：版本化模型、几何校验和原子本地存储。
- `apps/api/alpha.py`：鉴权后的读取/保存端点和标定页面模板入口。
- `apps/api/gauge_calibration.js`：冻结当前视野、向导状态、画布标点和提交。
- `tests/gauge/`：模型、环形刻度与存储的定向 Python 测试。
- `tests/frontend/gauge_calibration.test.mjs`：向导顺序、撤销和提交负载的定向测试。

读取算法、自动圆检测、定时任务、数据库和告警均不进入本次改动。

## 8. 定向验证与验收

遵循“小步开发＋定向测试”，本次只运行：

- 标定模型与存储测试；
- 标定页面 API 测试；
- 标定前端行为测试；
- 受影响 Python 文件编译和前端语法检查。

本次不运行全量 Python、全部前端、完整 CI 或全局发布门禁。阶段集成或大版本
发布时再统一执行全量验证。

本小步完成条件：

1. 可在 `2×/3×` 当前高清视野中完成两表盘标定；
2. 每个表盘能保存圆心、针尖和至少三个已知刻度；
3. 跨越 `0°` 的刻度模型可保存并正确校验；
4. 非法或不完整标定不会覆盖已有文件；
5. 真实参考图和 JSON 只存在于 i9 的 `runtime/calibration/`；
6. 定向测试通过后，再由 i9 做一次真实手工标定验收。
