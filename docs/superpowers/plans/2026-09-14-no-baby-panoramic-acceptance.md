# 无宝宝场景全景验收方案

## 1. 本次目标与证据边界

用户报告当前没有宝宝、只有空场景。本轮编制者只读取 GitHub 文档和代码，
没有连接摄像头、查看实时画面或确认安装环境。现场状态须由操作人在开始时确认，
不能把用户描述写成 AI 已观察到的事实。

一次集中检查大盘、低风险语音和空场景警报，减少反复现场操作。预计 60–90 分钟，
这是排期预算，不是性能指标或强制结束时间；未完成的配额记 PARTIAL，不删减为 PASS。
本次是原全景验收的有界子集，不能关闭包含真实宝宝正例的完整视觉验收。

本次请求授权编制并更新项目方案，不在本轮启动实机测试。后续操作人在登录的 i9
本地确认准备好后，按本方案集中执行；不通过聊天消息发出时间推断人已经准备好。
2026-09-04 的其他实机延期保持有效。

| 范围 | 本次可验证 | 本次不能证明 |
|---|---|---|
| 大盘 | 已安装版本、四 Tab、实时画面、统计与事件一致、手机布局 | 尚未实际查看的浏览器或设备 |
| 语音 | 无宝宝时模拟口令识别、唯一 i9 应答、独立计数 | 已喂奶、已换尿布、已拍嗝；护理数据已保存 |
| 空场景 | 有效画面下无新遮脸误报、事件去重、语音与视觉并行 | 宝宝遮脸/趴睡/离床的真实识别准确率 |
| 成人场景 | 可选成人进入/离开及不串扰遮脸风险 | 空白无床画面中的床位判断 |

## 2. 执行约束与准备

- 保持 Camera Reply=false、i9 扬声器输出、listen-only；不用摄像头应答替代失效的 i9 输出。
- 保持一个 Xiaomi 外部 producer、transport=auto，不开第二条摄像头连接，不调用 PTZ。
- 不启用 Baby Care 写入、签名、outbox、绑定或药物业务；不生成模拟护理记录。
- 不新增家庭截图、录像、录音、转写、私有语料或校准制品。既有生产事件按原策略运行；
  不清空数据库、不删除旧警报、不注入生产风险、不修改阈值或床区。
- 不主动点击测试通知或重新配置通知；既有服务可能正常产生文字通知，若发生仅登记
  聚合数量。通知送达不在本次 PASS 范围，不能声称所有自然通知均为零。
- 只读取本地闭合状态和聚合计数，不上传家庭媒体、模型原文、地址、路径、身份或凭据。
- 当前不能读到的指标写 NOT_OBSERVABLE，不能填 0；没有能力判断的步骤不能 PASS。
- 安装版本落后时先记 BLOCKED_VERSION，按既有安装流程处理后重新预检；本方案不提供
  未核实的新部署命令，不覆盖脏工作区、不整栈重启。
- 物理 iPhone 不在场时只完成实际使用的桌面端；手机项记 DEFERRED，不以响应式模拟替代。

开始前读取 AGENTS.md、四份交接文档、总交付计划、本方案及既有 Voice Task 8。
核对真实工作区、分支、HEAD、工作区改动、安装 HEAD 和资源版本。
本轮 GitHub 编制无法检查 i9 本地 dirty state；必须现场补证。

## 3. 执行顺序与检查表

### 0. 先由 i9 Codex 返回只读预检结果

- [ ] 先执行 [i9 Codex 交接提示词](2026-09-14-i9-codex-preflight-prompt.md)，
      只检查现有安装、状态、计数和接口，不开始本节 A–D 的实机矩阵。
- [ ] 将脱敏结果返回规划会话，据实际 HEAD、接口可用性和旧警报状态完善本方案。
- [ ] 当前方案为待现场信息校准版本；未知项不能按健康默认值补齐。
      i9 的只读预检可以先做，无需用户说话、摆放场景或等待手机。


### A. 本地预检与会话基线（约 10 分钟）

- [ ] 操作人确认无宝宝，并选择闭合场景码：EMPTY_BED_VIEW / ROOM_NO_BED /
      UNUSABLE_VIEW / UNKNOWN。不记录房间布局。无床或床区不可用不伪装为空床。
- [ ] 登录的 i9 保持醒着，现有 Voice 为健康 idle，i9 输出可用；操作人确认就绪。
- [ ] 记录代码/安装 HEAD、会话起止时间、时区、模型身份核验结果、视频推进、
      音频接收、producer 数与 Camera Reply=false，缺失项明确标记。
- [ ] 记录当前警报快照、Guardian/Voice 聚合计数和服务 generation/PID 连续性。
      使用前后差值，不清零生产计数；若重启或计数回退，结束该段并建立新会话。
- [ ] 使用仓库已核实入口做有界预检；`make alpha-guardian-test` 只能按原有
      无真实通知/无生产事件注入契约运行。命令成功不替代肉眼画面或听到回复的证据。

### B. 大盘实机检查（约 10–15 分钟）

- [ ] 桌面浏览器打开总览、警报、分析、系统四 Tab；标题、焦点、返回和刷新正常。
- [ ] 连续切换 Tab 10 次；实时画面继续推进，没有重复媒体节点或第二个源连接。
- [ ] 检查现有 HD/缩放功能；不点击会保存家庭图像的截图按钮，不重做标定。
- [ ] 警报筛选、时间、来源、未恢复数、今日恢复数与同一时间窗的只读投影一致。
      跨午夜或查询间有新事件时重新取同一窗口，不误判为统计错误。
- [ ] 分析 24h/7d 各查看一次并往返切换；空桶保持缺口、无分母为“无数据”、
      不可用不显示为 0。窗口边界按 API 时间与时区核对，历史数值不能算本次新增。
- [ ] 系统页显示有限公开状态，不出现凭据、原始异常或内部路径。
- [ ] 页面隐藏再恢复 3 次，检查无重叠轮询/重复定时器，旧响应不覆盖新状态。
      仅凭肉眼无法判定网络并发时记 NOT_OBSERVABLE，使用本地开发者工具补证。
- [ ] 在本地浏览器单独阻断 Dashboard 数据请求，观察首次不可用与后续过期状态，
      再恢复请求验证刷新；不关闭摄像头、M2 或生产服务。若浏览器不能安全定向阻断，
      此项记 NOT_RUN，引用已有软件证据而不扩展故障范围。
- [ ] 实际 iPhone 检查四 Tab、按钮、纵横屏、无遮挡/无横向溢出与实时画面。
      只测试现场设备，缺席设备明确 DEFERRED。

### C. 空场景视觉观察（语音前后各 5 分钟）

两段画面都须实际推进，worker 和语义观察须有新有效输出，不能以静止画面或模型
不可用时“零警报”判 PASS。同时记录有效观察数、不可用计数和实际覆盖时间。

- [ ] 语音前观察 5 分钟，记录新增 face watch/alert/event 的可观察计数。
- [ ] 语音结束后再观察 5 分钟，核对无语音串扰、无重复警报、状态没有挂起。
- [ ] 无宝宝期间零新增遮脸风险是目标；旧遮脸警报单独列出，不删除、不当新误报计数。
      若旧警报被新空场景错误延长，亦为失败，不只检查事件总数。
- [ ] 有效 outside 证据满足原确认规则时，允许既有离床风险生命周期；
      “没有宝宝”不等于“所有警报必须为零”。从未看到宝宝不用于宣称真实离床检测通过。
- [ ] 只有 UNKNOWN/UNUSABLE 或没有可用床区证据时，不要求生成离床警报；
      要求保持不可用/不确定而非伪造安全或某一风险。语义误识别记失败/待诊断。
- [ ] 已有遮脸风险只有两次合格、同因的 outside/no-baby 观察且跨既有确认间隔
      才能按 subject_outside 恢复；不手工注入旧风险以凑验收。
      没有对应历史状态时，此恢复项记 NOT_EXERCISED。
- [ ] Dashboard 的 resolution_cause 首期仍为 null；不得解析日志补造数据库字段，
      也不得把 subject_outside 恢复说成已确认宝宝面部安全。
- [ ] 成人进入/停留/退出为可选独立行：人愿意参与且原场景允许时做一轮，
      在既有确认时间内观察成人边沿、去重与零遮脸串扰。无人参与则 DEFERRED。
      不把成人、玩偶、屏幕视频当作宝宝正例。

判定：出现新遮脸 watch/alert/event，或无法归因的延长、重复输出时停止相关视觉门禁，
保留固定失败码与前后计数。不得只隐藏 UI 告警来通过。

### D. 喂奶、换尿布、拍嗝语音矩阵（约 25–40 分钟）

使用当前接受的合并单句路径。下表是预定义测试输入，不是家庭转写。
每次操作人看见本地提示后只说一次，等待应答和 idle，再进行下一次。
不能把第二次重说算成第一次成功。每个物理输入都有试次编号；只记录闭合动作码和结果。

| 动作 | 固定输入 | 正例配额 | 预期 |
|---|---|---:|---|
| feeding_command | 嘿，小小，我要喂奶了 | 10 次 | Feeding 计数 +1、完整可听 i9 应答一次 |
| diaper_change_start | 嘿，小小，开始换尿布 | 5 次 | diaper 计数 +1、唯一应答 |
| diaper_change_complete | 嘿，小小，换好尿布了 | 5 次 | diaper 计数 +1、唯一应答 |
| burping_start | 嘿，小小，开始拍嗝 | 5 次 | burping 计数 +1、唯一应答 |
| burping_complete | 嘿，小小，拍嗝结束 | 5 次 | burping 计数 +1、唯一应答 |

每组建立独立前后计数。若现有接口只给动作族计数，则逐次隔离 start/complete，
按提示试次记录证据，不能虚构接口暴露了更细的动作码。无法证明动作明细时注明限制。
任何漏识别、未听到、截断或重复，都保留分母并标 FAIL，不循环重试到全绿。

共用负例 20 次，作用于三类动作族：无唤醒、否定、取消/停止、疑问/近义非指令、
多动作冲突各 4 次。每组样本分布覆盖 Feeding、diaper 和 burping；
执行前把准确的预定义输入与当前已提交负例夹具核对，禁止临场改成更易通过的输入。
“跨动作”分两类：一个合法的其他动作应正确路由为该动作；多动作歧义才必须静默。
不把合法换尿布命令当作全局静默负例。药物口令不在本次矩阵内。

- [ ] 三个动作族分别达到全部正例唯一识别/唯一可听回复；共同负例零误接受。
- [ ] 核对其他动作族无错误增量、无 Baby Care 写入路径、无残留回复状态、
      无 producer 替换/摄像头移动、视频与视觉处理持续推进。
- [ ] 可在 D 全程观察实时画面，不另跑一轮重复语音来“测试并行”。
- [ ] 记录识别成功数、完整可听数、重复/漏识别/误接受数和可测延迟。
      没有分阶段时间戳时，不编造 ASR/TTS p95。

本次 PASS 标签为 COMBINED_COMMAND_DEVICE_PASS，仅针对该合并单句、当前说话人、
距离和声学条件。原 Task 8 的 armed follow-up 路径及历史两阶段失败仍保留；
本方案不以单句成功替代至少 10 次 Feeding follow-up 的原门禁，也不关闭完整 Stage 2。
如以后要验收两阶段路径，应另列矩阵，不能在现场无限扩展本次任务。
