# Qwen/Ollama Visual Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect the R2 visual capture pipeline to the fixed M2 Qwen3-VL model through a loopback-only Ollama client, deterministic model-health gate, production worker entrypoint, and independent macOS launchd services.

**Architecture:** The i9 worker calls only `http://127.0.0.1:11435/api/chat`; a separately managed SSH process forwards that loopback port to M2 `127.0.0.1:11434`. `OllamaVisualReviewer` accepts exactly four privacy-processed in-memory JPEGs and returns the existing strict `VisualReview`; `VisualReviewRuntime` feeds successful results into the existing deterministic risk state machine and separately tracks model degradation/recovery. The worker, tunnel, Dashboard, go2rtc, and environment worker remain independent processes.

**Tech Stack:** Python 3.11+, Pydantic 2, urllib, Ollama `/api/chat`, Qwen `qwen3-vl:8b-instruct-q4_K_M`, `concurrent.futures.ThreadPoolExecutor`, macOS launchd, OpenSSH, pytest.

## Global Constraints

- The model tag is exactly `qwen3-vl:8b-instruct-q4_K_M`; runtime settings cannot select another model.
- The client origin is exactly `http://127.0.0.1:11435`; the only request path is `/api/chat`.
- Ollama remains bound to M2 loopback `127.0.0.1:11434`; no `0.0.0.0`, router forwarding, Tailscale Funnel, or public endpoint.
- Requests contain exactly four privacy-processed JPEG byte strings, each at most 1 MiB and together at most 4 MiB; no file paths or URLs.
- HTTP uses no environment proxy, a 20-second timeout, `stream: false`, `think: false`, `temperature: 0`, and a five-minute model `keep_alive`.
- The response model name and strict schema-v1 body must match; raw output and underlying exceptions never enter health state, logs, or notifications.
- A single model failure does not degrade. Degrade after three consecutive failures or 60 seconds; recover only after two consecutive successes.
- Model output remains observation evidence. Only `VisualRiskStateMachine` opens or recovers risk alerts.
- R3 adds no SQLite events, media files, ntfy delivery, Dashboard routes, parent feedback, audio, external models, or device control.
- Tests use generated bytes and synthetic JSON only; no household media, credentials, private addresses, or SSH keys enter Git.
